# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回の app.ask は用語集を使わないため、「3レベル」の意味を一般的なAI講座の分類として推測で答え、講座固有の定義にはたどり着かなかった。エージェントは search_glossary で用語集を確認してから、基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）の3段階であり、どれか1つに取り組めば宿題が完了になることまで正確に答えた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：search_glossary({'query': 'LoRA'})、search_glossary({'query': 'QLoRA'})（質問「LoRAとQLoRAの違いは？」のとき）
- 1つの質問での LLM 呼び出し回数（`requests`）：2回
- 追加したツールと、docstring に書いた説明：make_quiz（引数 lecture: int）。docstring には「指定した回の用語から、確認問題を1問作って返す。『第N回の確認問題を出して』のように、ある回の復習のための確認問題を求められたときに使う。用語集からその回の用語を1つ選び、『○○の意味は？』という問題と、答え（その用語の定義）を返す。まず問題だけを出題し、利用者が答えたあとで答え合わせに使うこと」と書いた。`--trace "第2回の内容から確認問題を1問出して"` で make_quiz({'lecture': 2}) が呼ばれ、SFT の確認問題が出題された。pytest は 11 passed だった。

## 宿題

- 取り組んだレベル：基礎
- やったこと：app/tools.py の search_glossary の docstring を「query には調べたい用語を1つだけ入れる」から「query には調べたい用語をまとめて入れる」に書き換え、同じ質問「LoRAとQLoRAの違いは？」を `--trace` 付きで実行して、変更前後を比べた。
- 結果：変更前は search_glossary が {'query': 'LoRA'} と {'query': 'QLoRA'} の2回呼ばれた（tool_calls=2）。変更後は {'query': 'LoRA QLoRA'} の1回だけになった（tool_calls=1）。戻り値も、変更前は用語ごとの単一オブジェクトだったが、変更後は複数ヒットをまとめたリスト形式になった。回答の内容自体はほぼ同じで、LLM 呼び出し回数（requests）は前後とも2回で変わらなかった。
- 気づき・疑問：docstring の一文を変えるだけで、モデルの引数の作り方が変わることが確認できた。ツールへの指示はコードではなく自然文で書かれているため、その書き方がツールの呼ばれ方を大きく左右する。一方で、まとめて検索すると戻り値の形まで変わるので、ツール側の実装が複数ヒットに対応しているかも含めて確認が必要だと感じた。
